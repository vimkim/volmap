# Pinned CUBRID page corpus

This corpus contains complete 16,384-byte physical pages generated by CUBRID
commit `e1e651debf6cc100172bde96603b17424f9c135a`. All database content comes from
[`generate.sql`](generate.sql); there is no production or recovered data.

The page set preserves linked structural examples without committing the full
192 MiB source snapshot. It covers volume headers and bitmaps, the file tracker,
an extendible hash page, catalog, vacuum and dropped-file pages, heap header and
data pages, B-tree roots, a single-chunk OOS value, a three-chunk OOS value
chain, and the multipage-object overflow file created by the fixed-width row.
[`manifest.toml`](manifest.toml) records every page identity and SHA-256 digest,
the complete source-volume digests, generator versions, and semantic roles.

## Reproduction

Build and install the pinned engine in a clean worktree, initialize its runtime
environment, then run:

```sh
mkdir -p "$CUBRID_DATABASES/volmap_e1e651de"
cubrid createdb --db-page-size=16K --db-volume-size=32M \
  --log-volume-size=20M volmap_e1e651de en_US.utf8 \
  -F "$CUBRID_DATABASES/volmap_e1e651de"
csql -S -u dba -i fixtures/e1e651de/generate.sql volmap_e1e651de
```

Standalone `csql` exits after committing and flushing the snapshot. Extract a
page with a 16,384-byte block size and `skip=PAGE_ID`; volume 0 is the database
basename and volume 1 is its `_x001` extension. Compare the source and page
digests to the manifest before replacing any fixture.

The observed CUBRID minimum expanded the requested 32 MiB database volume to a
64 MiB primary volume and allocated a 128 MiB extension. That geometry is part
of this corpus identity.
