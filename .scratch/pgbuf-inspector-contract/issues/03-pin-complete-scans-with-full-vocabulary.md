# 03: Pin complete scans with the full semantic vocabulary

**What to build:** A Volmap implementer can decode canonical complete scans whose page frames use every page kind, latch mode, LRU zone and list kind the wire defines, with log positions and incarnation-local topology indices, and can rely on the contract's emission and sampling-coherence statements. The CUBRID serializer reproduces those scans, and its enumerator, latch and LRU mapping functions are proven on the branch under test.

**Blocked by:** 02 — Pin the handshake frames and the identity set.

**Status:** ready-for-agent

- [ ] The contract specifies `scan_request` (`type` only; a request never carries scope or caps), `scan_header` (`type`; `scan_seq` strictly increasing per incarnation across all clients and explicitly not an event sequence; `incarnation` equal to the hello's; `started_at_unix_ms` as display metadata, never freshness authority), `page` (canonical field order `type`, `volid`, `pageid`, `page_kind`, `latch_mode`, `waiter_present`, `fix_count`, `dirty`, `flushing`, `async_flush_requested`, `to_vacuum`, `lru_zone`, `lru_list_kind`, `lru_list_index`, `page_lsa`, `oldest_unflush_lsa`; only `type`, `volid` and `pageid` mandatory; the rest optional, with `lru_list_index` and both log positions nullable) and `scan_footer` (`type`; `scan_seq` equal to the header's; `page_count` as the exact number of page frames emitted, counted before any consumer deduplication; `truncated`; optional `truncation_reason`; `ended_at_unix_ms` as display metadata).
- [ ] The contract publishes the vocabularies: `page_kind` as Volmap's existing kebab-case names (`unknown`, `file-table`, `heap`, `volume-header`, `volume-bitmap`, `query-result`, `extensible-hash`, `overflow`, `oos`, `area`, `catalog`, `btree`, `log`, `dropped-files`, `vacuum-data`) plus reserved `unmapped`, mapped by engine enumerator name so one mapping serves both branches and `oos` appears only where its enumerator exists; `latch_mode` as `none`, `read`, `write`, `flush`, `invalid`, `unmapped`; `lru_zone` as `lru1`, `lru2`, `lru3`, `void`, `invalid`, `unmapped`; `lru_list_kind` as `shared`, `private`, `none`, `invalid` with the exact kind-local index arithmetic from the packed global index and the hello's counts, `null` for `none` and `invalid`, and indices scoped to the incarnation; log positions as objects of `pageid` and `offset`, `null` for the engine's null sentinel, never the packed word. It lists what is never on the wire: pointers, thread or process identities, raw flag words, raw page-type ordinals, packed LRU indices, native list counters, quotas, ticks, page contents or content hashes, paths and OS error text.
- [ ] The contract states the emission rule (a slot is emitted when its sampled identity is non-null, whatever the subsequent flags sample shows, including `invalid` or `void` zone; slots with a null identity are omitted; pages of temporary volumes are emitted and consumers ignore identities outside their inspected volumes; omission means observed non-residency only when the footer says the scan was complete) and the sampling-coherence statement (identity copied first; one atomic latch-word load for the latch tuple; one flags-word load for the flag and LRU tuple; page kind and page log position from the buffered page header; oldest unflushed position from the slot; each tuple coherent within its load and immediately volatile; frame and traversal non-atomic; VPID equality proves neither memory/disk correspondence, commit visibility nor durability).
- [ ] The serializer gains semantic header, page and footer values and the mapping functions: engine enumerator to page-kind name, decoded latch values to the latch tuple, and zone plus packed global index plus the two list counts to the LRU tuple, yielding `unmapped` for any input without a mapping. Extracting these inputs from engine words remains stage-two work; the module includes no engine internals.
- [ ] Cases exist: an empty complete scan (header and footer with `page_count` 0); a complete scan whose pages together cover every enum value including `oos`, `invalid` and `void` zones, `invalid` and `flush` latch modes, waiter present, shared and private indices, `none` with `null`, and both null and non-null log positions; two consecutive scans on one connection with increasing `scan_seq`; a `rate-limited` error followed by a later valid scan. Each expected outcome is `accepted-complete` with normalized decoded pages.
- [ ] Tests prove byte-exact reproduction of each stream; page-kind mapping for every enumerator present on the branch under test, asserting that `oos` is produced on the format-aligned branch; latch tuple mapping including `invalid`; LRU arithmetic at the shared, private and invalid bounds and for `none`; null versus non-null log-position rendering; `unmapped` for out-of-mapping inputs; the page-frame limit at 4,095, 4,096 and 4,097 bytes; and corpus integrity after regeneration with the revision incremented.
- [ ] Execution evidence with named cases and nonzero counts is recorded in this ticket's comments with the exact commit.
